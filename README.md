# GEOSENTRA

A frontend-only multi-hazard disaster-intelligence and relocation-planning prototype — landslide, flood, coastal erosion and cloudburst. Built for Smart India Hackathon (SIH26191).

- **Production:** https://geosentra.vercel.app/
- **Repository:** https://github.com/JananiTcoder/geosentra.git

This is a frontend prototype only. There is no backend, no database, no live sensor feed, and no trained ML model — every screen runs on mock data defined in `src/data/*.js`. See [`PROJECT_REPORT.md`](./PROJECT_REPORT.md) for the full, verified account of what is and isn't implemented.

## Getting started

```bash
npm install
npm run dev       # start the dev server
npm run build     # production build
npm run preview   # preview the production build locally
npm run docs:check  # sanity-check PROJECT_REPORT.md against the actual routes
```

## Documentation

**[`PROJECT_REPORT.md`](./PROJECT_REPORT.md) is the single source of truth** for what this application currently does — every page, route, map behavior, risk/relocation terminology, the actual design system, the actual tech stack, and current limitations. It is generated by reading the code, not by describing an intended design, and it is expected to be kept current.

A longer, non-technical narrative version of the same material — for demos, judging, and presentations — lives at `docs/geosentra-field-guide.html` and is also published as a Claude Artifact.

### Documentation update checklist

**Any pull request that changes the frontend must update `PROJECT_REPORT.md` in the same change.** Specifically:

- [ ] New page added → documented in `PROJECT_REPORT.md` (page list + route table).
- [ ] Route path changed → route table updated.
- [ ] Map marker, legend, or category changed → map section updated.
- [ ] Navigation/click behavior changed → the relevant page's "User actions" updated.
- [ ] Mock data changed in a way that's visible in the UI → the relevant page/data section updated.
- [ ] Deployment configuration changed → the deployment section updated.
- [ ] A feature was removed → removed from `PROJECT_REPORT.md`, not left describing something that no longer exists.

Before committing, run:

```bash
npm run docs:check
```

This runs `scripts/check-documentation.mjs`, a lightweight drift check — it confirms every route in `src/App.jsx` is mentioned in `PROJECT_REPORT.md`, that no known-removed feature is described as current, and that the production/GitHub URLs are present. It cannot understand UI behavior, so passing it is not a substitute for actually reading the diff against `PROJECT_REPORT.md` — it only catches the cheap, mechanical kind of drift.

Full maintenance rules live in `PROJECT_REPORT.md` under **Documentation maintenance checklist**.
